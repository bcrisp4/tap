# Coordinator notes — cross-spec invariants and review log

This file is the working memory of the cross-spec coordinator agent during the M7–M12 spec authorship round (2026-05-10). It captures (a) the foundational invariants from M1–M6 that no later milestone may silently violate, and (b) the watchlist of cross-milestone tensions surfaced during parallel brainstorming. Conflict resolutions ultimately landed in the milestone specs themselves; this file remains useful as a durable index of the invariants and as scratch space for future cross-spec work.

## Foundational invariants from M1–M6 — must not be silently violated

- **Single static binary, pure-Go, CGO_ENABLED=0** (concept §6.1, M1). No CGO deps anywhere; SQLite is `modernc.org/sqlite`. M9 (FTS5) and M11 (archival) need to verify their dependency choices keep this.
- **Database is the queue** (concept §6.2). No separate queue table or in-memory queue. M11 archival ticker should follow the same shape (one ticker; idempotent passes).
- **Single-transaction commit per poll** (concept §6.15). M11 tombstone insertion + entry delete must hold the same atomicity.
- **All outbound HTTP through one shared `httpx.NewClient`** (concept §6.4 + §6.8). SSRF re-checked on redirect. Per-host cap default 4. Anything in M7+ that does outbound HTTP must reuse this client.
- **Loopback-default bind** (concept §6.11). M12 hardening must not flip this.
- **Credential redaction invariant** (concept §6.10, M6). Write-only fields, never returned on reads. The DTO write-shape and read-shape are physically distinct types. M7 user-credential-equivalent fields (TOTP secrets, passkey private metadata) must follow the same shape.
- **SPA does NOT run runtime sanitiser** (concept §6.6). Every entry HTML path must flow through `processor.Process` (sanitise + image rewrite). Extracted, future-imported, or M11-tombstone-replayed content all share this requirement.
- **Auto-mark-read fires once per entry per page lifetime** (concept §6.13). M8/M10 must keep this contract.
- **Per-feed credentials NEVER applied to media-proxy origin fetches** (M6). Same-origin authenticated images render broken; intentional, mirrors Miniflux. M9/M10 must preserve this.
- **Multi-user data isolation is M7 work, not M6.** Subscriptions/entries currently have no `user_id`. The intended posture per roadmap.md M7 row is **strict per-user privacy with no admin override on feed visibility.** Even admins see only their own feeds. M9 (categories, OPML, search) and M11 (archival) need to scope queries by user.

## Watchlist for cross-milestone conflicts

### M7 ↔ M11 — `user_id` migration vs archival sweep
- **RESOLVED (2026-05-10):** Tombstones use `(subscription_id, entry_hash)` PK with `ON DELETE CASCADE` to subscriptions. No `user_id` column needed — FK chain `tombstone → subscription → user` provides per-user scoping transitively. Cascade on user delete works correctly. Global archival sweep (no per-user filter) is intentional for M11; per-user horizon prefs are deferred to a FUTURE milestone (NOT M7 — M7's spec does not include `users.archive_horizon`). M11 migration is `0010_tombstones.sql` (not 0006 — collision corrected).

### M9 ↔ M11 — FTS5 index sync with archival deletes
- **RESOLVED (2026-05-10):** M9 commits to AFTER INSERT / AFTER UPDATE / AFTER DELETE triggers on `entries` to keep the FTS index in sync automatically. M11's archival sweep deletes from `entries` directly and the triggers handle FTS automatically — M11 does NOT need an explicit FTS sync call. M11 spec must include a regression test: run an archival sweep, then assert FTS search returns no results for deleted entries and still returns results for retained ones.

### M7 ↔ M10 — CSRF rotation, session expiry, mutation queue
- M6 says CSRF token rotates only on password change. M10 offline mutations queued in localStorage. When the user comes back online and the queue replays, the queued requests carry the CSRF token current *at queue time*. If the user changed password offline (impossible) or the session expired, replays fail.
- M10 needs a defined behaviour: 401 on replay → drop queue or surface to user? 403 csrf_invalid → re-bootstrap auth and replay with new token?
- Idle TTL is 7d default; absolute is 90d. A user offline for >7 days returns to expired session. M10 must handle this gracefully (queue persists; on reconnect, login → drain).

### M8 ↔ M10 — theme-color, density, manifest
- M8 ships the three themes. M10 PWA manifest's `theme_color` must agree with one of them (or auto-resolve to current theme via JS at install time).
- M8 stores theme as a per-device preference in browser localStorage (concept §12 says theme is per-device, not in DB). M10 service-worker shell must not bake one theme in.
- Reader auto-mark-read (concept §6.13) — M8 is responsible for the keyboard/swipe surface; M10 for the offline mutation enqueue. Both must agree on the trigger semantics.

### M12 ↔ M7 — metrics labels and data model
- M12 metrics include "auth events" and "polling per-feed cadence" — these must label by `user_id` once M7 lands, but a high-cardinality label is a foot-gun. Need a decision on whether per-user labels are even shipped, or only aggregate.
- M12 brute-force lockout per-source + per-username — must work pre-M7 (single admin) and post-M7 (multi-user) without a redesign.

### M9 ↔ M10 — OPML import format, offline support
- OPML imports may be large. Body cap (1 MiB on writes per CLAUDE.md) is too small for a typical OPML — needs a separate cap or a per-route override.
- M10 service worker should NOT cache an in-progress OPML import response.

### M8 ↔ M9 — search UI vs SPA polish
- **RESOLVED (2026-05-10):** `/` keybinding ships in M9 alongside search, NOT in M8. M8's keyboard shortcut surface omits `/` entirely — not a stub, just absent until M9. M9 spec must document this explicitly; M8 spec must list `/` focus-search in its out-of-scope table with "lands in M9".

### M11 ↔ M3 — media cache eviction model
- M3 ships inline LRU under cap pressure. M11 ships daily age-based sweep. Both must agree on the sidecar metadata format and the safe-to-delete contract (no in-flight handler holding a path open while the sweeper unlinks it). M3 used `os.Rename` atomic writes; M11 needs to handle `ENOENT` gracefully when a `.bin` is gone but `.meta` remains.

### M11 ↔ M2/M3 — re-imports and tombstones with credential context
- Tombstones consult on insert (concept §6.9). If a feed re-publishes after a tombstone, it doesn't reappear. If user A and user B subscribe to the same feed (M7), do they share tombstones or not? **Privacy posture says no — strict per-user isolation.** Each user's tombstone table is per-user.

### M7 ↔ M6 — argon2 params, recovery codes hashing
- M6 used `auth.DefaultParams` (t=2, m=64MiB). M7 should reuse — recovery codes are short single-use, but the hash should still be argon2id with the same params for consistency. M7 SHOULD NOT re-define hashing primitives.

### M10 ↔ M3 — offline image caching via service worker
- **RESOLVED (2026-05-10):** M10 SW uses CacheFirst for `/api/v1/proxy/*` layered on top of M3's Go-side FS cache. No Go changes needed. Warm-cache driver must use plain `fetch(url)` (NOT `fetch(url, {cache:'force-cache'})`): plain fetch goes through the SW fetch handler and populates the Workbox `tap-proxy-{userId}` cache; `force-cache` bypasses the SW and populates the browser HTTP cache only — bug found in M10 draft, flagged for correction.

### Foundational invariants to re-verify in plans

Same as spec phase — flag any plan that:
- Introduces a CGO dependency (violates pure-Go invariant).
- Constructs an `http.Client` outside `httpx.NewClient` (shared client invariant).
- Adds a sanitisation step in the SPA rather than server-side (runtime sanitiser invariant).
- Omits `MaxBytesReader` on a new write handler.
- Breaks single-transaction commit per poll.
- Puts per-user data isolation logic outside the DB layer (must be in query, not in handler).

### TDD discipline

Every plan task that touches logic, branches, state, or error handling must be sequenced as red → green → refactor. Flag any plan that:
- Groups implementation and tests into a single step rather than distinct red/green tasks.
- Labels a task "write tests" after the implementation task rather than before.
- Exempts behaviour-bearing code from TDD without a spec-level justification.
- Does not reference `superpowers:test-driven-development` skill.
